refactor(locators): per-page CSV locators with module-scope loading

Replaces the single root Locators.text with one CSV per page, and mirrors the
Java repo's static-block pattern:

    // ByLoginLocators.ts
    export const LOCATORS = loadLocators('Login');
    export const By = {
      USERNAME_FIELD: select(LOCATORS, 'usernameField'),
    } as const;

TypeScript has no `static { }` initialiser block, so loadLocators('Login') runs
at module scope. That is the same guarantee - it executes exactly once, on first
import of the page's locator module.

Files:
  Locators/reads_CustomLogin.csv     -> ByLoginLocators.ts
  Locators/reads_CustomAccount.csv   -> ByAccountsLocators.ts
  Locators/reads_CustomCustomer.csv  -> ByCustomerLocators.ts

Each page passes its OWN map to select(...), so a lookup can never resolve a key
from another page's CSV. A missing key fails fast with the available keys rather
than surfacing later as a Playwright timeout.

Removed: Locators.text, src/locators/Locators.ts.
LoginPage.ts now reads ByLoginLocators.By.* instead of Locators.Login.*.

Verified: tsc --noEmit clean; playwright test --project=ui-chromium 8 passed.
